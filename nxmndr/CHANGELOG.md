# Changelog

## Unreleased

### Breaking changes

Server and proxy:
- The gRPC server binds 127.0.0.1 by default (was every interface, `[::]`), and `nxmndr-server --host` now sets the gRPC address as well as the HTTP proxy's; an IPv6 address may be given with or without brackets (`::` or `[::]`). Operator: pass `--host 0.0.0.0` to accept other machines, after reading [Security](README.md#security).
- The HTTP proxy (`nxmndr-server --azure-proxy`, `python -m nxmndr server`, `python -m nxmndr.server.azure_openai_proxy`) binds 127.0.0.1 by default (was 0.0.0.0). `python -m nxmndr grpc` gains `--host`. Operator: pass `--host 0.0.0.0` to accept other machines.
- For OpenAI-platform endpoints the proxy sends the configured deployment as `model` and replaces a `model` field from the client (was: the client's value was forwarded). Client: select the model with the deployment in the route.

Model loading (`LoadModel`, `UnloadModel`):
- `LoadModel` with a spec equal to that of a loaded model returns that model's `model_id` (`effective_metadata` has `model_cache_hit=true`) and loads no second copy (was: every `LoadModel` loaded a new copy under a new `model_id`). `UnloadModel` releases one `LoadModel` reference, also while a session or call uses the model. When no reference is left, the model is freed at once if no session or call uses it, and otherwise as soon as the last session or call that uses it ends, unless a `LoadModel` takes a new reference first (was: `UnloadModel` freed the model at once, and failed with `FAILED_PRECONDITION` while a session or call used it). A `LoadModel` whose client is gone when the load finishes (its deadline passed or it cancelled) keeps no reference; one that its client gives up on after that moment keeps its reference. Client: call `UnloadModel` once for each successful `LoadModel`.
- The server keeps at most `NXMNDR_MODEL_CACHE_CAPACITY` models (default 10). A new model at full capacity evicts the least recently used model that no session or call uses, also one whose `LoadModel` callers have not unloaded it, and `Predict` with its `model_id` then fails with `NOT_FOUND`. If every loaded model is in use, `LoadModel` fails with `RESOURCE_EXHAUSTED` (was: models stayed loaded until `UnloadModel`). Client: on `NOT_FOUND` call `LoadModel` again, or run tiles through a session (`OpenSession`), which keeps its model loaded until the session closes.
- `LoadModel` with `overwrite=true` fails with `FAILED_PRECONDITION` while a session, a running call or an earlier `LoadModel` caller holds the loaded model (was: `overwrite` was ignored and every `LoadModel` loaded a new copy). Client: unload your own `model_id` first; the next `LoadModel` then loads a new copy unless another caller, a session or a running call still holds the model.
- `LoadModel` and `OpenSession` refuse a non-empty `ModelSpec.preprocessing` or `ModelSpec.postprocessing` with `INVALID_ARGUMENT` (was: ignored). Client: send empty lists and build the preprocessing into the exported model.

Sessions, streaming and capabilities (`OpenSession`, `StreamPredict`, `Capabilities`):
- Every message of a `StreamPredict` tile carries `context["tile_id"]`; a message without it ends the stream with the stream-scope error `missing_tile_id` (was: not required). An `end_of_sequence` message with no chunk and no `tile_id` still ends the open tile. Client: set `tile_id` on every message (`InferenceGrpcClient.stream_predict` does).
- Per-tile options are read only from `context["opt.<name>"]` on the tile's first message (was: every context key of the tile's first message with a context was an option). Other context keys, apart from `session_id` and `tile_id`, are ignored, and the server logs each such key name once per stream at WARNING. Client: rename `key` to `opt.key` on the tile, or send session-wide options without the prefix in `OpenSessionRequest.options`.
- A segmentation tile returns the mask alone (`payload_format` `raw`); mask and confidence come as a tensor bundle only with the option `return_confidence=true` (was: a stream always returned the bundle with confidence). Client: send `opt.return_confidence=true` on the tile, or `return_confidence=true` in `OpenSessionRequest.options`.
- `batch_size`, as a context key or a session option, no longer batches tiles: the server runs the tiles of a stream one at a time in arrival order (was: tiles ran in batches of `batch_size`). Client: remove it, and keep several tiles in flight with `transport.max_inflight`.
- A stream whose `session_id` was not opened with `OpenSession` fails with `NOT_FOUND` and the stream-scope error `unknown_session` (was: the stream created the session). Client: call `OpenSession` first.
- A dropped stream closes its session with reason `disconnected`, and a stream-scope error closes it with reason `failed` (was: the session stayed open). The closed `session_id` stays reserved for `NXMNDR_SESSION_TTL_SECONDS`, and `OpenSession` with it fails until then. Client: open a new session with a new `session_id` and send the unfinished tiles again.
- A session idle longer than `NXMNDR_SESSION_TTL_SECONDS` (default 3600) is expired by a sweep that runs every 60 seconds from server start, and its model is unpinned (was: idle sessions expired only when another `OpenSession` arrived, at most once a minute). A stream on an expired session ends with a stream-scope error (`error_code` `session_not_open`), and `CloseSession` reports status `expired`. A session with a running stream is never idle. Client: open a new session after a long pause, or raise the TTL.
- `Capabilities` leaves out `pytorch_model_classes` and `pytorch_model_input_sizes` when the server cannot list its PyTorch model catalog, and `pytorch_model_input_sizes` leaves out a name whose input size cannot be read; both failures are logged on the server (was: `Capabilities` failed with `UNKNOWN`). Client: treat an absent entry as unknown, as for a server from before the entry.
- `Capabilities` `stream_max_chunk_bytes` is 133169152, the gRPC message limit minus 1 MiB for the message's other fields (was 134217728, the limit itself), and `OpenSession` refuses a `transport.chunk_bytes` above it with `INVALID_ARGUMENT` (was: accepted, and then the first full message ended the stream with `RESOURCE_EXHAUSTED`). `NXMNDR_STREAM_MAX_CHUNK_BYTES` above that value is lowered to it, with a warning. Client: negotiate at most `stream_max_chunk_bytes`.
- `OpenSession` refuses a negative `transport.max_inflight` with `INVALID_ARGUMENT` (was: accepted and returned as the session's `max_inflight`); 0 still takes `stream_max_inflight`. The server refuses to start (`ValueError`) when `NXMNDR_STREAM_MAX_INFLIGHT` is below 1 (was: every session got that window, which the client refuses). Operator: set it to 1 or more, or leave it unset (16).

SAM 3 prompts (`opt.sam_*` options, `nxmndr.models.sam`):
- `sam_input_points` is `[[x, y], ...]` and must come with `sam_input_labels`, `[1, 0, ...]` of the same length (1 positive, 0 negative) (was: a list of `[[[x, y]]]` entries, every label positive). Client: send both lists.
- All points and the box form one object prompt, which returns one mask (was: one mask per point, and a box ran as its 4 corner points, which gave 4 masks). Client: expect one mask per prompt.
- A malformed SAM option is refused; a stream tile fails with `malformed_options` (was: a logged warning, and the model ran without that prompt). Client: send valid JSON.
- A SAM prompt needs a `uint8` chip; a chip of another dtype is refused, and a stream tile fails with `malformed_payload` (was: cast with `astype("uint8")`). Client: convert native samples to 8-bit display values before sending.
- `is_sam_model` and `generate_grid_points` are removed (was: `is_sam_model` routed by the model's name, and `generate_grid_points` made a point grid). Client: read `capability.sam` from `LoadModelResponse.effective_metadata`, and send explicit points.

PyTorch models (generic `PYTORCH` specs, run in the PyTorch RPC worker):
- On a CUDA host the spawned worker builds every PyTorch model on the first GPU of the server's device plan (`cuda:0`) and applies the server's cuDNN policy (was: always on the CPU). The `device_id` and `device_type` metadata of a PyTorch `Predict` response or stream tile name the device that ran the model, `cuda:0` and `gpu` or `cpu` and `cpu` (was: the device plan entry picked for the call, such as `cpu:2`, which did not run the model). One inference call in the worker fails after 60 s (was 5 s). Operator: the worker's CUDA context and models use memory on `cuda:0` beside the server's own.
- A class registered with `register_pytorch_model` loads its weights file strictly, as catalog models do. Every failure of that load fails `LoadModel` and `OpenSession` with `INVALID_ARGUMENT` and a one-line message that says what is wrong: the file is missing; `torch.load` with `weights_only=True` refuses it; it is not a state dict, a mapping of entry names to tensors (for example a checkpoint that nests the state dict under a key, or holds a value that is not a tensor), and the message lists its first keys; it lacks one of the model's entries, has an entry the model does not have, or has an entry of another shape, and the message names the first such entry; or `load_state_dict` fails for another reason, and the message has the first line of its error (was: the file loaded with `strict=False`, so entries the model does not have, such as a nested state dict, were ignored and the layers the file did not fill kept their random initial values; the other failures were `INTERNAL` with the worker's traceback). Embedder: save the full `state_dict()` of the registered class, not a checkpoint that wraps it.
- `stop_server` (and `serve` when it returns) stops the PyTorch RPC worker after the model cache (was: the worker ran until the process exited or the embedder called `service.rpc_manager.shutdown()`, which is now a no-op after `stop_server`). A later server in the same process refuses generic PyTorch models with a message saying that they need a server in a new process (was: refused as "another server in this process already runs the PyTorch RPC worker"). Embedder: start each server that serves PyTorch models in its own process.

PyTorch RPC worker network (`MASTER_ADDR`, external mode with `NXMNDR_RPC_EXTERNAL_WORKER=1`):
- In external mode the RPC group listens on 127.0.0.1 unless `MASTER_ADDR` is set (was every interface, `0.0.0.0`), and in both modes an empty `MASTER_ADDR` means 127.0.0.1 (was every interface). The server binds the rendezvous store on `MASTER_ADDR` only (was: torch's store listened on every interface whatever `MASTER_ADDR` named, also for the spawned worker). Operator: for a worker on another host, set `MASTER_ADDR` to an address of the server host that the worker can reach, on a trusted network only ([External Worker Mode](README.md#external-worker-mode-worker-on-another-host)).
- An external worker keeps its report connection to `MASTER_PORT + 1` open until it exits, and the server reads the connection closing as the worker's exit (was: the connection closed after `ok`, and the server counted the worker as alive until it stopped it). After the worker exits, PyTorch `Predict` fails with `UNAVAILABLE` and a new `StreamPredict` ends with a stream-scope error (both `rpc_worker_not_available`), and loads fail naming the worker's pid and host (was: `Predict` failed with `INTERNAL` and torch's connection error, and so did loads). A worker of an earlier version closes the connection after `ok`, so the server counts it as disconnected at once. Operator: run the same nxmndr version on the worker host as on the server, and restart a running external worker after upgrading.
- In external mode with a non-loopback `MASTER_ADDR`, `LoadModel` and `OpenSession` refuse a generic `PYTORCH` spec with uploaded `artifact` bytes with `FAILED_PRECONDITION` (was: the server saved the bytes on its own host and the worker opened that path on its own host, which can read it only through a shared filesystem). Client: send `source` with the weights path on the worker host.
- In external mode with a worker on another host, the model cache keys a `source` path by the size and modification time of the file on the server host, so a PyTorch weights file retrained in place on the worker host is served from the cached model until that model is evicted, or freed when every `LoadModel` caller has unloaded it and no session or call uses it; if the path also exists on the server host, the file there decides when the model loads again (was: every `LoadModel` loaded a new copy, which read the file again). Client: write retrained weights to a new path, or unload the model before you load it again.

Client (`nxmndr.client`):
- An `https://host[:port]` endpoint opens a TLS channel, default port 443 (was: the scheme was removed and the client dialed plaintext). Client: use `grpc://host:port`, `http://host:port` or `host:port` for a plaintext server.
- `http://host` without a port means port 80 (was: the scheme was removed and gRPC chose the port). Client: give the port.
- `InferenceGrpcClient` retries a unary call only when it fails with UNAVAILABLE (was every status code). A call that fails with INTERNAL or another server answer, or whose deadline passes, raises `InferenceGrpcError` after one attempt. Client: give slow calls (an `open_session` or `load_model` that downloads a model) a longer `timeout`, and retry a failed call yourself only where running it again is safe.
- An error no longer closes the client's channel (was: every failed call or stream closed it, which also ended every other call in progress on the same client). After a server outage the channel reconnects with gRPC's backoff, which can take several seconds. Client: call `close()` to open a new channel on the next call at once.
